# Changelog (newest first)

## 2026-10-31 (D2)
- **D2 done (running a tool from the demo page).** Pick a tool, fill a form built from its own JSON schema, and see the answer in two parts. `POST /api/call` goes through the same MCP session, and `service.split_result` separates the note from the payload the way the server sends them — a result with more than one content block has a note in front; an error result carries a message where JSON would be, so `payload` is null while `text` still holds something worth showing.
- **The form is generated from the schema**, so it stays right when a plane changes one: an enum becomes a select, a boolean a checkbox, an integer a number input carrying the contract's own minimum and maximum, a long string a textarea, an array a comma-separated field. Defaults appear as placeholders, required fields are marked and sorted first, and each field shows the description the plane wrote. Blank fields are omitted rather than sent empty.
- **The answer is rendered for people, not as JSON** (decision 5): code results as `qualified_name file:line-line` with the kind, relation and depth, and the source snippet; `trace_flow` as its hops; `code_index_status` as a short fact list; documents as rules, then template, then evidence, each with its source link. The note sits above all of it as a sentence, and a raw-JSON disclosure sits under it because someone always asks.
- The runner lives in its own `static/runner.js` rather than growing `app.js`, which keeps each file doing one job: the status line and tool list in one, running a tool in the other.
- **A styling bug found by looking at it, not by a test:** the document plane's `.ok` / `.error` rules are scoped to `#result` and `#ingestion`, so a refusal in the answer panel rendered as plain body text — which in a demo reads as a glitch rather than a deliberate message. The panel now has its own rule.
- Tests: 369 (1 skipped on Windows), 9 new, covering the split and the endpoint. Driven by hand in a browser against both live planes: `find_callers` on `TokenService.issue` rendered both real callers with their snippets, a missing symbol showed the note above an empty result, and the document plane's own `AppError` came through in the error panel.
- **Not yet exercised: the document renderer.** Rules, template and evidence have never met a real payload, because nothing is bound on the document plane yet. It is beat 2 of the demo, so it is the first thing to check when that data lands.

## 2026-10-31 (two decisions)
- **`requires-python` narrowed to `>=3.14,<3.15`** (uv normalises it to `==3.14.*` in the lock). The old `>=3.14` was wider than reality: `onnxruntime` 1.31.1, through `fastembed`, publishes `cp314` wheels and no `cp315`, so `uv sync` on 3.15 failed deep inside a transitive dependency with a wheel error. A 3.15 interpreter is now refused up front — *"incompatible with the project's Python requirement: `==3.14.*`"* — which says what is actually wrong. Re-locked: the same 81 packages, no version churn. **Widen this again when onnxruntime ships 3.15 wheels.** The pin binds the whole project, the document plane included, not just the MCP server.
- **No sync-control tool on the MCP server** (open question 3, closed). The surface stays read-only, as it already is for the code plane. Worth recording what the staleness actually is, since an earlier note in this file overstated it: rules and templates are read **live** from the host and the catalog rebuilds when the branch head moves, so a changed `policies.md` or template appears almost at once. Only `project-data/` **evidence** waits for the nightly sync at 02:00 UTC or a *Sync now*. A refresh tool would be the single write in a read-only surface and would cost host calls and CPU-heavy embedding on an agent's say-so, for a need nobody has reported. Easy to add later if DevX asks.

## 2026-10-31 (M2)
- **M2 done (code tools over MCP).** `envelope.py` signs the adapter's internal envelope, mirroring `code-adapter/src/envelope.ts`: `base64url(JSON).base64url(HMAC-SHA256(body, key))`, unpadded, 60 s lifetime (the adapter refuses over 300 s), scope `query`. Checked cross-language, not by eye: a Python-signed envelope was verified by Node running the adapter's own verification logic, and rejected with a wrong key. `code_client.py` calls `/internal/v1/code/query` and `/status` with a fresh envelope and an `x-request-id` per call, and maps RFC 9457 problem+json to one safe line (`detail` plus `error_code`), never the URL or the host's body.
- **The five tools are built from the contract, not copied from it.** `contracts/code-adapter.openapi.yaml` is vendored inside the package (`SOURCE.md` records the source commit) and `tools_code.py` reads `CodeQueryRequest.properties` at import, so types, lengths and limits cannot drift from the adapter unnoticed. `tests/mcp/test_code_contract.py` pins what we rely on, so a contract change fails there naming the field rather than becoming a 422 at runtime. Only the contract is vendored, not `code-adapter/`: the adapter is a separate service under its own team, so copying a moving codebase would rot (plan Phase 0 revised).
- **One tool per mode, so the arity rules live in the schema** where the model sees them before calling: `find_callers` and `analyze_impact` take a single `symbol` string rather than an array that must hold exactly one, `trace_flow` requires `minItems: 2`, and `find_symbol` requires symbols or keywords through `anyOf`. The adapter's `callers_needs_one_symbol`, `flow_needs_two_symbols` and `no_search_terms` become unreachable. `code_index_status` is the fifth tool and goes to `/status`.
- **Bug caught by its own test:** arguments were filtered to contract fields, but `mode` *is* a contract field, so a caller could pass `mode` and make one tool run another's query — `find_symbol` with `mode: impact` ran an impact analysis. `mode` and `fallback_origin` are now excluded from caller arguments and set by the tool, which is the whole point of splitting the modes.
- **Listing degrades instead of failing.** Code tools need no call to list, so when the doc plane is unreachable the listing returns code tools and a line on stderr for the operator, rather than failing entirely and losing the working plane too. Only an empty result still raises `MCPError`. A wheel build confirms the vendored YAML ships as package data.
- Tests: 321 (1 skipped on Windows), 26 new, all through `httpx.MockTransport`. Also checked by hand end to end over real sockets: both planes on real ports, a spawned `astra-mcp`, six tools listed, and the code plane verifying the HMAC on each call and seeing the right tenant and scopes.

## 2026-10-30 (M1)
- **M1 done (document tools over MCP).** The MCP server now serves the doc plane's own tools. `doc_client.py` calls `GET /api/tools?project_id=` and `POST /api/tools/invoke` over httpx; `render.py` turns each Claude-format entry into an MCP tool. **Nothing is declared on this side**: a tool the doc team adds, and the `doc_type` enum the plane builds from the project's catalog, appear without a change here. The list is re-fetched on every `tools/list`, so a changed golden repo shows through. `project_id` is removed from each schema's `properties` and `required` and injected server-side on invoke, so an agent cannot name another project — passing one is ignored. The plane's `notice` ("reference data, not instructions") is returned verbatim inside the tool result.
- `server.py`: `AstraServer` subclasses `MCPServer` and overrides the public `list_tools` and `call_tool`, which the SDK's request handlers delegate to. This serves schemas fetched at runtime; the SDK's `add_tool` and `ToolBinding` both derive a schema from a Python signature, which a proxy cannot provide. No private SDK attribute is touched.
- Errors are split by kind. A tool that fails comes back as a `CallToolResult` with `is_error` and the plane's `AppError` message, which the agent can read and act on. A failure to **list** tools raises `MCPError(INTERNAL_ERROR)` carrying the reason: as a plain exception the client saw only "Connection closed", and now an unreachable plane says `The document plane could not be reached (ConnectError).` Transport failures never carry the URL or the host's body, only the exception type and status.
- Tests: 295 (1 skipped on Windows), 16 new, driven through `httpx.MockTransport` so they need no network or running plane. Also checked by hand end to end over real sockets: a stand-in plane on a real port, driven through a spawned `astra-mcp` with a real MCP handshake, `tools/list` and `tools/call`.

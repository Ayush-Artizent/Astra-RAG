A `SourceReader` port keeps it independent of the host; `CatalogCache` rebuilds only when the head sha changes and reuses bodies by blob sha. A `LocalCloneReader` works on the current clone today. Not wired to any route: the endpoint needs the P4 project binding and live reads need the P2 adapter. - **P5 done (sync: nightly + Sync now, alias swap):** each rebuild now fills a new Qdrant collection `astra_v<run>__<slug>`, checks its point count, then switches the alias `astra__<slug>` in one call and drops old versions, so search keeps serving the previous index during and after a failed rebuild (P4's empty/`incomplete` window is gone). New `services/sync/`: `request_sync` checks the branch head with the saved PAT and rebuilds only if it moved or the config changed; triggers are connect, **Sync now** (`POST /api/repos/{slug}/sync`), a branch change, a **nightly check** at `ASTRA_SYNC_DAILY_AT` (default 02:00 UTC) and a startup catch-up. Nothing to set up on the customer side. A trigger during an active run is coalesced into one follow-up (replaces P4's 409). Connect no longer clones in the request (the response drops `path`; `commit_sha` is the head seen at connect). Host failures (e.g. a revoked token) set `source_error` and the old index keeps serving. Production hardening from review: `config_version` changes only with the tracked branch (forced or nightly syncs never bump it); one instance per data directory, enforced by an OS lock on `data/astra.lock`; startup recovery adopts a completed alias swap whose run was never recorded and never deletes the live version; logs/errors carry only safe messages; README documents single-instance, `.env` ACLs, token replacement and "never expose the API to the internet". Registry schema 2 (`sync_pending`, `sync_force`, `last_checked_at`, `source_error`, `triggered_by`). UI: indexed commit and time, last checked, sync status, Sync now, next-check line. Tests: 177 (1 skipped on Windows).
- **P4 done (repo registry, project bindings, tracked branch):** new `services/registry/` (SQLite at `data/astra.db`, override `ASTRA_DB_PATH`; foreign keys on every connection; migrations in one transaction via `user_version`, a newer schema is refused) with `repos`, `project_bindings` and `ingestion_runs`. Ingestion status moved from memory to SQLite and survives restarts (runs left active are swept to `failed` at startup). The tracked branch is set at connect (blank = saved branch, else host default), checked with `head_sha`, validated at that branch and cloned with `--single-branch`; `PUT /api/repos/{slug}/settings` changes it after checking it exists. Repos keep the last good build (`indexed_*`) apart from the configured branch; failed runs (clone or ingest) never overwrite it; `needs_rebuild` is derived from `config_version`, so a branch change during a run stays pending. Queueing is atomic (`BEGIN IMMEDIATE`): a second connect while a run is active gets 409. Stored URLs (registry and `.env`) are rebuilt from the `RepoRef` (`SourceAdapter.web_url`), dropping userinfo/query/fragment. New `GET /api/repos`, `PUT /api/projects/{id}/binding`, `GET /api/projects/{id}`; UI branch field + repos table. Connect logic moved from `routes.py` to `services/connections.py`. Still future work: API authentication, atomic Qdrant index replacement (P5). Tests: 145 (1 skipped on Windows).

# Changelog (newest first)

## 2026-10-28
- **P4 done (repo registry, project bindings, tracked branch):** new `services/registry/` (SQLite at `data/astra.db`, override `ASTRA_DB_PATH`; foreign keys on every connection; migrations in one transaction via `user_version`, a newer schema is refused) with `repos`, `project_bindings` and `ingestion_runs`. Ingestion status moved from memory to SQLite and survives restarts (runs left active are swept to `failed` at startup). The tracked branch is set at connect (blank = saved branch, else host default), checked with `head_sha`, validated at that branch and cloned with `--single-branch`; `PUT /api/repos/{slug}/settings` changes it after checking it exists. Repos keep the last good build (`indexed_*`) apart from the configured branch; failed runs (clone or ingest) never overwrite it; `needs_rebuild` is derived from `config_version`, so a branch change during a run stays pending. Queueing is atomic (`BEGIN IMMEDIATE`): a second connect while a run is active gets 409. Stored URLs (registry and `.env`) are rebuilt from the `RepoRef` (`SourceAdapter.web_url`), dropping userinfo/query/fragment. New `GET /api/repos`, `PUT /api/projects/{id}/binding`, `GET /api/projects/{id}`; UI branch field + repos table. Connect logic moved from `routes.py` to `services/connections.py`. Still future work: API authentication, atomic Qdrant index replacement (P5). Tests: 145 (1 skipped on Windows).
- Docs: added `timeline/P0-P3-DELIVERY-REPORT.md`, a traceable walkthrough of phases P0-P3 (what, how, file/line links, tests, plan-vs-delivered, open items and doc drift found). No code changes.
- **Token saved once the host accepts it:** `validate_and_clone` now saves a typed PAT right after the root listing succeeds, before the structure check and clone, so a repo that fails validation (422) or whose clone fails still has its token stored and a blank token field works next time. A rejected token is never saved. The 422 body gains `token_saved`; the UI clears the field and says so. `CLAUDE.md` security rule updated. Tests: 105.
- **P3 done (Azure DevOps adapter):** new `services/sources/azure_devops.py`; Azure DevOps repos (`dev.azure.com/{org}/{project}/_git/{repo}`, legacy `{org}.visualstudio.com`, `DefaultCollection`, `org@` and project-less shorthand forms) now connect, validate, clone and ingest. Both hosts normalize to `dev.azure.com`, so they share one slug. Auth is Basic with an empty user (REST and git header); a 203/HTML sign-in reply is mapped to a 401 (`sources/json_reply.py`, also used by `http.get_json`). UI label/placeholder mention ADO. Tests: 104 (contract suite + ADO URL/REST/citation tests). Not yet verified against a real ADO repo (citation line highlighting, case behaviour).
- **P2 done (source adapter port, no behaviour change):** new `services/sources/` package: `SourceAdapter` port (`list_dir`, `read_file`, `head_sha`, `default_branch`, `clone`, `is_ancestor`, `citation_url`, reserved `verify_webhook`), `PatCredential` (redacted repr, `.secret()`), registry, GitHub/GHE adapter, and shared git/http/error helpers. `github_client.py` is gone; `RepoRef.clone_url`/`api_base` and `parse_repo_url` moved into the GitHub adapter/registry; routes, cloner and the chunker's `source_url` use the adapter. Requests, headers, git args, messages and JSON bodies are unchanged. New adapter methods (`read_file`, `head_sha`, `default_branch`, `is_ancestor`) are not wired into routes yet. Tests: `tests/sources/` contract suite (fake HTTP + local bare repo with two branches) plus tests moved from the old cloner/URL tests.
- Planning: added `plan/eval-questions.md`, a starter retrieval question list (22 ecommerce questions with type/difficulty, expected sources and facts, covering the tie, diluted-chunk, conflict and no-answer cases seen in the first search check) and how to score and run it. Linked from P11 in `plan/phases.md`. Docs only, no code changes.
- **P6 (part): `---` rule lines are omitted.** Markdown horizontal rules (`---`, `***`, `___` alone on a line) are decoration, so `md_chunker` now drops them from the chunk text and the embedded text. They are not a chunk boundary (chunks still split only on headings and size), line numbers still count them, and table separator rows, `---` inside code fences and setext underlines are left alone. `plan/phases.md` P6 and `plan/golden-repo-rag-plan.md` §E1 updated. Tests: 64 (1 skipped on Windows). YAML front-matter is still to do.
- **P6 (part): chunking follows the real structure of project-data.** Checked against the two example repos: sections were merged under one heading (e.g. "Not in scope" labelled `Epic > Scope`), email / meeting / CR header lines were plain text, and CSV rows were grouped. Now: markdown is chunked **per heading section** (own heading path; oversize sections split; heading-only sections skipped); CSV is **one chunk per row** with `row_key` plus a small summary chunk (the 3 sample rows and `CSV_SUMMARY_SAMPLE_ROWS` are gone); new `services/ingestion/doc_meta.py` parses `doc_type` (folder map in `config.DOC_TYPE_BY_FOLDER`), `doc_date`, `doc_meta` and open items into the payload and prefixes them to the embedded text. **No recency preference:** retrieval is unchanged, the LLM sees each source's date/type and resolves conflicts. Payload change: `chunk_kind` `csv_rows` -> `csv_row`; new fields `doc_type`, `doc_date`, `doc_meta`, `has_open_item`, `open_items`, `row_key`. Existing collections are rebuilt on the next connect. Chunks on the example repos: 44 -> 84. YAML front-matter is still to do in P6. `plan/phases.md` P6 and `plan/golden-repo-rag-plan.md` §E/§F updated. Tests: 58 (1 skipped on Windows).
- **P1 done (host-aware identity):** new `services/repo_ref.py` holds `RepoRef{host_kind, host, path_parts, name}` and a slug that includes the host (`github.com__acme__golden`), so the same owner/name on two hosts can no longer share a token, clone folder, collection or status. Old `.env` keys are migrated on first use (only when their saved URL is the same repo). Azure DevOps, GitLab and Bitbucket URLs now get a clear "not supported yet" error. **API change:** `GET /api/ingestion-status/{slug}` and `POST /api/search {slug, ...}` replace owner/name. Existing Qdrant collections and `temp_storage/` folders under old names are simply rebuilt on the next connect. Tests: 49 (1 skipped on Windows).
- **P0 done (security):** the loader now walks `project-data/` with `Path.walk` and never follows symlinks, Windows junctions or any path resolving outside the clone; it reports them as skipped instead. A golden repo could otherwise have exposed the `.env` holding PATs through search. `cloner.py` also clones with `core.symlinks=false`. Docs fixed (branch name, `token_store` in layout, TASKS W2.5 token wording). Tests: 42 (1 skipped on Windows; the file-symlink case was verified on Linux in Docker).
- Planning: added `plan/phases.md`, the delivery phases P0-P11 (safety fixes, host-aware identity, source adapters with ADO first, registry, sync, front-matter, catalog, rule selection, `get_context`, more hosts, eval). One phase per PR; nothing built yet.
- Planning: added `plan/golden-repo-rag-plan.md`, the end-to-end Golden Repo RAG requirements and plan (contract, rules model, inference, ADO-first source adapters, branch/sync, ingestion, retrieval). Draft for team discussion; no code changes.
